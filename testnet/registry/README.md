# Testnet Contract Registry

## Overview

This directory (`testnet/registry/`) serves as a lightweight, integrator-facing mirror of **"what's live on testnet right now"**. It is explicitly a **read-oriented companion** to (not a replacement for) the excluded `deployments/testnet.json`.

## Purpose

| This Registry (`testnet/registry/`) | Deployments Artifact (`deployments/testnet.json`) |
|---|---|
| Human-readable documentation | Machine-readable deployment output |
| Curated by maintainers | Generated by deploy script |
| Explains status, caveats, procedures | Records contract IDs, WASM hashes |
| Updated manually after verification | Updated automatically by deploy pipeline |
| Includes operational runbooks | Pure data |

## When to Update This Registry

| Trigger | Action |
|---|---|
| Contract deployed to testnet | Update `contract-status.md` + `last-verified.json` |
| Contract upgraded | Update `upgrade-history.md` + `wasm-hash-reference.md` |
| Health check performed | Update `last-verified.json` timestamp |
| Admin/controller address changed | Update `admin-addresses.md` |
| New known test account created | Update `known-test-accounts.md` |
| Incident investigated | Add findings to relevant runbook |

## Relationship to `deployments/testnet.json`

```
deploy.sh (or CI)
       │
       ▼
deployments/testnet.json  ───►  testnet/registry/ (manual curation)
       │                            │
       │ Raw deployment output      │ Human-readable + procedures
       │ Contract IDs, WASM hashes  │ Caveats, runbooks, verification
       ▼                            ▼
   Source of truth            Integrator reference
```

**Update Process**:
1. Deploy script writes `deployments/testnet.json`
2. Maintainer verifies contracts using `verify-contract-live.md`
3. Maintainer updates `testnet/registry/` files with verified data
4. `last-verified.json` updated for automated staleness checks

## Automated Staleness Detection

A future CI job/bot can:
1. Read `last-verified.json`
2. Check if any contract timestamp > 30 days old
3. Alert maintainers to re-verify

```json
// last-verified.json format
{
  "ephemeral_account": "2026-09-24T00:00:00Z",
  "sweep_controller": "2026-09-24T00:00:00Z",
  "reserve_contract": "2026-09-24T00:00:00Z",
  "account_factory": "2026-09-24T00:00:00Z"
}
```

## For Integrators

Start here:
1. **Check status**: `contract-status.md` - what's deployed?
2. **Get contract IDs**: From `contract-status.md` table
3. **Verify health**: Run `verify-contract-live.md` procedures
4. **Subscribe to events**: Use `event-topics.md` for indexer filters
5. **Handle errors**: Consult `runbooks/` for failure scenarios

## For Maintainers

Workflow:
1. Deploy contracts (updates `deployments/testnet.json`)
2. Verify each contract (`verify-contract-live.md`)
3. Update `contract-status.md` with IDs, WASM hashes, caveats
4. Update `last-verified.json` with current ISO timestamp
5. Update `wasm-hash-reference.md` with commit→hash mapping
6. If upgraded, log in `upgrade-history.md`
